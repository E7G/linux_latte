# MiPad2 7.2 r4: permanent PLL routes deployed

## Status: 2026-10-24 (CONT23)

The production codec conditional I2S1/I2S2/I2S3 -> PLL routes and the board
Platform Clock -> PLL supply dependency are now in a full kernel image, not
temporary runtime route modules. Image source: `69bb7d3fbea73093bed7b7bcf060472ecb5bfea0`.
Running release: `7.2.0-mipad2-integrated-r4` after exactly one guarded warm reboot.
This is not an S5 power-off/cold-start qualification or Android-equivalence claim.

## Build and deployment

- W=1, LLVM/Clang21, thin LTO, bzImage and all 31 modules built in an isolated r4
  directory. Config exactly matches r3; all seven protected r3 artifacts unchanged.
- Three existing LTO stack-frame warnings retained: AtomISP sh_css_params (1128),
  fs/select (1064), zstd HUF_readCTable (1352). Not a zero-warning full build.
- All 31 module CMS signatures cryptographically checked. Native Arch package
  generated by makepkg, queried through ALPM and passed read-only preflight.
  The local Arch package is not PGP-signed and was not installed via pacman.
- Device payload isolated under `/var/lib/mipad2-kernel/7.2.0-mipad2-integrated-r4`
  and its own module tree. GRUB's raw Btrfs file reads compared with full payloads.
  Early USB serial initrd generated and verified; boot partition not filled.
- Single-use GRUB entry consumed; default remains `mipad2-bqdiag1` rescue.
  Existing kernels, camera launcher and userspace libraries preserved.
- Running embedded config/image hashes and five actually loaded driver srcversions
  match the staged build. 2163 protected installed files unchanged. 51 read-only
  smoke checks passed, including native binding of both sensors and focus actuator.
  These are discovery checks, not fresh optical/recording tests.

## Permanent-image audio/PM tests

Neither `mp2_pll_route` nor `mp2_board_pll` was present at any r4 checkpoint.
All tests played digital-zero PCM only, with no forced register writes, cache
replay, resume repair script, codec rebinding or DSP/MTP programming.
The read-only probe compares owning regmap reads with bypassed hardware reads.

| Test | S0I3 increment (us) | Post-resume RT5659 0x65 | Both amp status |
|---|---:|---:|---:|
| audio-pm | 11738176 | 0x0040 | 0xd85f/0xd85f |
| audio-pm-repeat | 12070080 | 0x0040 | 0xd85f/0xd85f |

Both consecutive 12-second RTC cycles passed residency, OS resume, camera/ISP
runtime-PM and actual PLL/amp-ready gates. Filtered ftrace shows 0x65 first
becoming zero during suspend, then PLL demand and 0x65=0x0040 after resume.
Thus the fix does not keep the PLL forced on throughout sleep. No trace overruns
or new fault markers. Wake IRQ9 is shared, not unique wake-source attribution.
USB was attached; these were not pristine untethered power-consumption tests.

Each probe was unloaded; all PCM ended closed, RTC cleared, tracing removed and
both test units terminal. Raw serial/kernel/ftrace logs remain tablet-private;
only register values, transition kinds and aggregates are published. The early
Linux banner was not captured on the late USB console; exact running identity
was established independently via SSH, proc config and loaded modules.

RT5659 0x82 cache=12288/hardware=12289 remains a retained healthy difference.
Do not call it cache corruption or claim all 33 registers match. Kernel taint
was 1088 before the unsigned external read-only probe, 13376 afterward; unloading
does not clear taint. No new acoustic listening test was performed on r4.

## Remaining work

The prior user-confirmed audible tones were on r3 with temporary routes, not r4.
R4 still needs fresh human acoustic/stereo/mic/headphone checks, S5 reliability,
full normal camera capture/recording/preview-resume regression and long-run/DMA
hang work. Idle audio graph power remains open despite the passed RTC residency.
Factory DSP remains unselected; UCM/profile/calibration-MTP policy and a full
mutually exclusive alternative build are prerequisites before activation.
Auto-lock, DPMS and automatic suspend remain disabled as requested; manual
authentication untouched. Thermal guard and no-idle service remain active.
